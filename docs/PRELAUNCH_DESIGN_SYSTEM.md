# Celestial industrialism

Near-black navy `#080d13`, steel/graphite surfaces, warm ivory `#eee9de`, metallic
gold `#d8bf8d`, restrained blue-grey metadata and real-result status colors.
Editorial Georgia/Cormorant fallback, system sans-serif body and Consolas metadata;
no remote font or visual dependency. Existing REQUIEM crest and celestial artwork
are retained. No invented customer logos, testimonials, performance or savings.

The hero's procedural mechanical model is the signature illustration. It reuses
the existing base/spacer/cover/fastener geometry and local lighting. The engine's
actual normalized tabletop zones are not represented as a physical measured CAD
reconstruction. The hero can orbit/select/explode; scroll adjusts separation until
the visitor uses a control. Pause and reduced-motion controls remain meaningful.

`HeroAssembly` and the large Three.js scene are separate lazy imports. Mobile and
reduced motion default to the technical SVG. A lost graphics context switches to
the same usable schematic and disables repeated 3D initialization. Only one hero
canvas is initialized; offscreen motion stops. The public demo does not require
WebGL. The full workspace retains its own original illustration.

The standalone public stylesheet is loaded before the marketing/demo routes. The
original workspace styles load with `/app`, retaining its existing layout and
source/evidence rendering. Navigation uses ordinary production-refreshable links;
there is no forced intro, scroll-jacking or required hover interaction.

Page sequence: hero → procedural problem → working demo → Observe/Verify/Preserve
→ available versus experimental → planned/exploring roadmap → early-access setup
→ prototype/privacy notice. The demo uses a source/evidence cockpit, not repeated
marketing cards. Decorative orbit bounds must not create horizontal scrolling.

The public proof asset `frontend/public/assets/prelaunch/product-proof.png` is an
unaltered real application capture from the prior rehearsal. Its copied source,
SHA-256 and population are in the adjacent `provenance.json`. It includes generated
fixture pixels and advisory guidance. The file is not a new result or generated UI.

Contact opens a reviewed `mailto:` draft only when an authorized address is
configured. It does not store or send submissions. Empty configuration remains
explicit. Source images/overlays are never color-filtered as decoration.
